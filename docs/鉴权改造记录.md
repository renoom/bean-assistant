# 鉴权改造记录：Console 统一网关 + 助手不鉴权

> 更新日期：2026-10-03
> 范围：`console/`、`assistant/`、`assistant-godot/`

## 1. 最终模型

```text
App / Godot / 浏览器 / Console UI
  │  持有平台 API Key
  ▼
Console（注册中心 + 配置中心 + 网关）
  │  校验平台 API Key
  │  sessionId -> 内网 host:port
  │  转发 HTTP / SSE / WebSocket
  ▼
助手进程（只监听 127.0.0.1 / 内网）
  │  不校验客户端 Key
```

原则：

- 外部只开放 Console 网关端口。
- 助手端口不对外暴露。
- 只有 Console 网关做入站鉴权。
- 助手不保存客户端 Key，也不校验客户端 Key。
- 平台只有一把 Key，Console UI 和外部客户端共用。


## 2. 一把 Key

保存位置：

```text
~/.assistant/console/api-key.json
```

```json
{
  "version": 1,
  "key": "ask_xxxxxxxx",
  "createdAt": "...",
  "updatedAt": "..."
}
```

使用方：

- Console UI：调用 Console 管理 API。
- App / Godot / 浏览器：调用 Console 网关 `/a/{sessionId}/*`。
- 助手进程：不使用这把 Key。

## 3. Console 内部接口

助手需要调用 Console 的接口：

```text
POST /api/register
POST /api/heartbeat/:id
GET  /api/config/resolve
GET  /api/skills/:name
GET  /api/skills
GET  /api/knowledge
GET  /api/knowledge/search
GET  /api/knowledge/:id
POST /api/knowledge/write
```

这些接口对**本机直连**放行，不需要 Key；如果经过反向代理或来自远程，则仍然需要平台 Key。

判断条件：

```text
req.socket.remoteAddress 是本机 127.0.0.1 / ::1
并且请求没有 X-Forwarded-For / X-Real-IP
```

这保证：

- 本机助手可以无 Key 访问 Console。
- 公网请求经过 Nginx 后带 `X-Forwarded-For`，不会被误判为本机。
- Console UI 和其他远程调用仍需平台 Key。


## 4. 代码改动

Console：

- `console/src/auth.ts`：生成、保存、校验一把平台 API Key。
- `console/src/gateway.ts`：`/a/{sessionId}/*` HTTP/网络代理与 SSE/WS 透传。
- `console/src/server.ts`：
  - `/api/*` 和 `/a/*` 统一校验平台 Key。
  - 助手内部接口对直连本机放行。
  - `/api/assistants` 返回 `gatewayBase` / `gatewayWsPath`。
  - 轮换 Key 不再推送助手。
- `console/src/spawner.ts`：不再向助手注入 Key。
- Console UI：
  - 平台 API Key 管理。
  - 轮换 Key 后刷新助手 iframe。
  - iframe 内不再弹浏览器 prompt。

Assistant：

- 删除 `assistant/src/auth.ts`。
- `HttpService` 不再校验收到的 HTTP 请求。
- WebSocket Upgrade 不再校验收到的 WS 连接。
- 助手访问 Console 的注册、心跳、配置、技能、知识库请求不再携带 Key。
- `bin.ts` 不再读取 `--api-key` / `ASSISTANT_API_KEY`。

## 5. 外部客户端接入

客户端只配置：

```text
gatewayUrl = http://127.0.0.1:3000 或 https://app.example.com
apiKey     = ask_xxxxxxxx
```

流程：

```text
GET  {gatewayUrl}/api/assistants
     Authorization: Bearer {apiKey}

HTTP {gatewayUrl}{gatewayBase}/api/message
SSE  {gatewayUrl}{gatewayBase}/api/stream?api_key={apiKey}
WS   {gatewayUrl 换成 ws}{gatewayWsPath}?api_key={apiKey}
```


## 6. 部署要求

Console 默认监听 `0.0.0.0:3000`，方便 Nginx / 网关转发：

- Nginx 和 Console 同机时，Nginx 可以转发到 `http://127.0.0.1:3000`。
- Nginx 在容器或另一台机器时，转发到 Console 所在内网 IP。
- 只允许本机访问时，可以用 `--host 127.0.0.1` 启动 Console。
- Console 启动助手时使用独立的 `--assistant-host`，默认 `127.0.0.1`，不会跟着 Console 绑到 `0.0.0.0`。

1. 助手只监听 `127.0.0.1` 或内网网卡。
2. 公网只放行 Console 网关端口。
3. 防火墙 / 安全组 / K8s NetworkPolicy 只允许网关访问助手端口。
4. 反向代理必须设置 `X-Forwarded-For`，避免远程请求被误判为本机。
5. 不要把助手端口映射到公网。

## 7. 验证记录

- Console `npm run build` 通过。
- Assistant `npm run build` 通过。
- Assistant `npm test`：16/16 通过。
- Godot `./run.sh test`：76/76 通过。
- 网关冒烟：
  - `GET /a/{sessionId}/` 无 Key 返回 200 静态 HTML。
  - `GET /a/{sessionId}/api/echo` 无 Key 返回 401。
  - 带平台 Key 返回 200。
  - 转发到助手时不再注入 Key。
- 助手内部接口冒烟：
  - 本机不带 Key 调用 `/api/register` 返回 201。
  - 本机不带 Key 调用 `/api/config/resolve` 返回 200。
  - 带 `X-Forwarded-For` 后返回 401。
  - 管理 API `/api/assistants` 无 Key 返回 401。

## 8. 后续 SSO

后续接 SSO 时，只需要改 Console 网关：

```text
平台 API Key 校验
  ↓ 替换为
SSO Access Token / Console 签发 Token 校验
```

助手侧没有入站鉴权，不需要接 OIDC；但后续如果要把用户身份传给助手，建议由网关注入并签名的内部 Header，而不是客户端自报。
