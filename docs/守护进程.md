# Console 守护进程（macOS launchd）

本方案用 macOS 原生 `launchd` 给 Console 做两层守护：

| 层 | 机制 | 覆盖场景 |
| --- | --- | --- |
| 主进程守护 | LaunchAgent + `KeepAlive` | 登录自启；进程退出、崩溃、被 kill 后自动重启 |
| 健康监控 | 定时探测 `GET /api/health` | 进程还在、但已经“假死”（事件循环阻塞、请求超时）时主动重启 |

Console 以**单进程**方式运行：`node --import tsx src/bin.ts`。
（不要再用 `tsx` CLI：它会 fork 子 node，`SIGTERM` 转瞬即被 relay 成 `SIGKILL`，
`ExitTimeOut`/优雅关闭都会失效，杀进程时还容易留下占端口的孤儿。）

健康监控逻辑：

- 每 30 秒探测一次 `http://127.0.0.1:3000/api/health`
- 要求 HTTP 200、响应含 `"ok":true`，且响应里的 `pid` 与端口 LISTEN 进程一致
  （避免端口被别的服务占用时把别人的 200 当成自己健康）
- 连续 3 次失败（约 90 秒）→ `launchctl kickstart -k` 重启 Console
- 重启后 15 秒仍不健康，按“端口归属”决定兜底动作：
  - 端口无监听：`bootout` + `bootstrap` 完整重启
  - 监听进程属于 Console：`kill -9` 该 listener，交给 `KeepAlive` 拉起
  - 端口被其他进程占用：只告警，不误杀，停止自动重启
- 两次自动重启之间至少间隔 60 秒（冷却），避免配置错误时疯狂重启

健康接口返回示例：

```json
{"ok":true,"name":"AI 助手控制台","assistantCount":5,"pid":80918,"uptimeSeconds":42}
```

> 这是 **liveness（存活）** 检查，不校验业务依赖是否正常；`ok:true` 只代表 HTTP 服务可应答。

## 文件位置

仓库内（源码与运维脚本）：

```text
console/ops/macos/install-console-daemon.sh        安装（两个 LaunchAgent）
console/ops/macos/status-console-daemon.sh         查看状态 / 健康 / 日志
console/ops/macos/uninstall-console-daemon.sh      停止并卸载
console/ops/macos/healthcheck-console-daemon.sh    健康探活 + 自愈脚本（源码）
```

安装到用户目录的运行时文件：

```text
~/Library/LaunchAgents/com.assistant.console.plist
~/Library/LaunchAgents/com.assistant.console.healthcheck.plist
~/Library/Application Support/assistant-console/healthcheck-console-daemon.sh   ← 安装时复制的副本
~/Library/Logs/assistant-console/                                              ← 日志与状态
```

> 健康检查脚本必须放在 `Application Support` 下运行：macOS 的 TCC 会阻止
> launchd 启动的进程读取 `~/Documents` 里的脚本（报错 `Operation not permitted`，
> 退出码 126）。安装脚本会自动复制，仓库里的文件仍然是唯一维护源；
> **改完健康检查脚本后需要重跑安装脚本**，副本才会更新。

## 安装

在项目根目录执行：

```bash
cd <项目根目录>

./console/ops/macos/install-console-daemon.sh
```

安装脚本会：

1. 找到当前 `node` 的绝对路径（支持 nvm），确认 `node_modules/tsx` 存在。
2. 生成 Console 与健康监控两个 plist。
3. 复制健康检查脚本到 `~/Library/Application Support/assistant-console/`。
4. **端口占用预检**：3000 上如果已有非 Console 进程，拒绝安装并提示，不会误杀。
5. 卸载同名旧服务，只停止属于 Console 的旧监听进程，并等待端口释放。
6. `launchctl bootstrap` 启动 Console，然后校验：
   `health 200` + `health.pid == LISTEN pid` + launchd `state = running`。
   校验不通过会打印 `console.err.log` 尾部并 **exit 1**（不会假报“安装完成”）。
7. 注册健康监控 LaunchAgent。
8. 输出端口监听与健康检查结果。

默认参数：

```text
Console:   0.0.0.0:3000
助手:      127.0.0.1
探活间隔:  30s
失败阈值:  3 次
重启冷却:  60s
```

## 查看状态

```bash
./console/ops/macos/status-console-daemon.sh
```

会输出：两个 launchd 服务的 state/pid/last exit code、`/api/health`、
3000 端口监听、健康监控状态文件、以及 Console 和监控日志尾部。

> 健康监控是定时任务，平时 `state = not running` 且 `last exit code = 1` 是正常的：
> 1 表示“本次探测失败但未达重启阈值”，0 表示健康或已自愈。看 `console-health.state`
> 与 `watchdog.log` 更直观。

也可以手动查看：

```bash
launchctl print gui/$(id -u)/com.assistant.console
launchctl print gui/$(id -u)/com.assistant.console.healthcheck
lsof -nP -iTCP:3000 -sTCP:LISTEN
```

## 日志

目录：`~/Library/Logs/assistant-console/`（权限 700，日志文件 600）

```text
console.out.log        Console 标准输出（追加，重装不清理）
console.err.log        Console 标准错误
watchdog.log           健康监控的失败与自愈记录（健康时不写，超过 5MB 自动轮转）
watchdog.out.log       健康监控进程自身的输出（每次安装重置）
watchdog.err.log       健康监控进程自身的错误（每次安装重置）
console-health.state   连续失败次数、上次重启时间、上次检查结果（每次巡检更新）
```

`console.out.log` / `console.err.log` 超过 50MB 时会被健康监控原地截断，
避免长期运行（Console 会转发所有助手 stdout）把磁盘写满。

实时查看：

```bash
tail -f ~/Library/Logs/assistant-console/console.err.log
tail -f ~/Library/Logs/assistant-console/watchdog.log
```

## 手动重启 / 停止

手动重启 Console（改完代码后用这个重载）：

```bash
launchctl kickstart -k gui/$(id -u)/com.assistant.console
```

`kickstart -k` 先发 `SIGTERM`，Console 会执行 `dispose()/save()` 优雅关闭后再被拉起；
`ExitTimeOut` 为 20 秒，超时才会强杀。

停止并卸载（日志保留，运行副本删除）：

```bash
./console/ops/macos/uninstall-console-daemon.sh
```

卸载只停止属于 Console 的监听进程；3000 上的其他服务不会被误杀。

## 自定义参数

安装时通过环境变量覆盖默认值：

```bash
CONSOLE_HOST=0.0.0.0 \
CONSOLE_PORT=3000 \
CONSOLE_ASSISTANT_HOST=127.0.0.1 \
CONSOLE_HEALTH_INTERVAL=30 \
CONSOLE_HEALTH_THRESHOLD=3 \
CONSOLE_HEALTH_COOLDOWN=60 \
./console/ops/macos/install-console-daemon.sh
```

只想保留“崩溃重启”、不要健康监控：

```bash
CONSOLE_HEALTH_WATCHDOG=0 ./console/ops/macos/install-console-daemon.sh
```

如果使用 nvm 且切换了 Node 版本，重新执行一次安装脚本，让 plist 记录当前 Node 绝对路径。

## 只生成 plist 做检查（不安装）

```bash
DRY_RUN=1 ./console/ops/macos/install-console-daemon.sh
plutil -lint /tmp/com.assistant.console.plist
plutil -lint /tmp/com.assistant.console.healthcheck.plist
```

注意：DRY_RUN 只生成 plist 供检查，不复制健康检查脚本，生成的 plist 不能直接 bootstrap。

单独演练健康检查脚本（不触发真实重启）：

```bash
./console/ops/macos/healthcheck-console-daemon.sh \
  --port 3000 --threshold 2 --cooldown 60 --dry-run \
  --log-dir /tmp/watchdog-test --state-dir /tmp/watchdog-test
```

## 演练：确认守护真的生效

```bash
# 1) 当前 pid 与健康状态
lsof -tiTCP:3000 -sTCP:LISTEN
curl -s http://127.0.0.1:3000/api/health

# 2) 模拟崩溃：kill -9 后应自动重启（默认 ≤10s+启动时间）
kill -9 "$(lsof -tiTCP:3000 -sTCP:LISTEN)"
sleep 12
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/api/health   # 期望 200

# 3) 模拟假死：SIGSTOP 冻结进程，健康监控应在约 90~150s 内自动恢复
kill -STOP "$(lsof -tiTCP:3000 -sTCP:LISTEN)"
sleep 150
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/api/health   # 期望 200
tail -n 20 ~/Library/Logs/assistant-console/watchdog.log
```

## 注意

1. `launchd` 保证“进程退出后重启”，但**不会**因为源码变化自动重载；改完代码执行一次 `launchctl kickstart -k gui/$(id -u)/com.assistant.console`。
2. 健康监控只判断接口可用性，不做业务断言；如果 Console 启动配置错误，`console.err.log` 是首要排查点。
3. 安装/卸载脚本只操作 Console 自己的监听进程；`CONSOLE_PORT` 被其他服务占用时会拒绝安装或跳过，不会误杀。
4. 这是用户级 LaunchAgent，登录后运行；未登录时不会启动。需要开机未登录也运行，要改造成 LaunchDaemon，并另外处理用户目录与权限。
5. 公网只应暴露 Nginx 的 443；Console 即使监听 `0.0.0.0:3000`，也要由防火墙限制只允许 Nginx 访问。
6. 首次启动（`~/.assistant/console/api-key.json` 不存在）会把完整 API Key 打印到 `console.out.log`；日志已收紧为 600 权限，仍建议首次安装后检查并妥善保存。
7. 健康监控的 `kill -9` 兜底只作用于**端口归属于 Console 的 listener**，不会按进程组误杀 Console spawn 的助手，也不会碰外部进程。
8. 如果 `status` 里健康监控显示 `last exit code = 126`，通常是脚本被 TCC 拦在 `~/Documents`，重新执行安装脚本即可修复。
9. 主进程仍从 `~/Documents` 加载 `src/bin.ts`，当前 Node 可正常读取；若换机/换 Node 版本后 launchd 下出现 `Operation not permitted`（install 校验会失败），需要给该 Node 授予“完全磁盘访问权限”，或把项目移到非 TCC 保护目录后再装。

## 排错

```bash
# 服务是否加载、状态如何
launchctl print gui/$(id -u)/com.assistant.console
launchctl print gui/$(id -u)/com.assistant.console.healthcheck

# 最近一次退出原因（137 = 被 SIGKILL，143 = SIGTERM）
launchctl print gui/$(id -u)/com.assistant.console | grep -E 'state =|pid =|last exit code|runs ='

# 健康监控最近一次判断
cat ~/Library/Logs/assistant-console/console-health.state
tail -n 30 ~/Library/Logs/assistant-console/watchdog.log

# 端口被谁占用
lsof -nP -iTCP:3000 -sTCP:LISTEN
```
