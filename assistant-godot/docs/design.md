# assistant-godot 框架设计

> 视觉小说形态的助手客户端。
> 本文是**设计文档**,不含实现代码。图见 `docs/diagrams/*.puml`。

---

## 1. 目标与非目标

### 要做到的

| # | 需求 | 落在哪一节 |
|---|------|-----------|
| 1 | 能正常给助手发消息、收回复 | §4 §6 |
| 2 | 会话记录默认隐藏 | §11 |
| 3 | 助手有虚拟形象,视觉小说式对话 | §9 §10 |
| 4 | 客户端能提供额外的系统提示词 | §7 |
| 5 | 完全不展示工具调用与思考过程 | §8 |
| 6 | 回答简洁,静默做事,只报结果;有疑问用对话反问 | §7 §9.4 |
| 7 | 给 AI 一个工具,让它自行调背景与表情 | §9 §10 |

### 明确不做的

- 不做多会话 / 会话切换 —— dsh 是**一个进程一个 session**,这是平台约束,不在客户端绕。
- 不做助手管理(创建、配置、模型选择)—— 那是 console 的活。
- 不做移动端。桌面(macOS 优先)即可。
- 不在客户端执行 AI 给的任意代码。§10.5 会说明为什么。

## 2. 先说清楚:为什么必须动服务端

现有平台的三条硬约束(已核对源码,不是猜测):

| 约束 | 现状 | 影响 |
|------|------|------|
| 传输 | 只有 `HTTP + SSE`。`docs/protocol.md` §2.6 写的 `WS /ws/chat` **没有实现** | 只能单向收,客户端没法回传任何东西 |
| 工具 | 只能服务端 `ctx.tools.register()` 静态注册,协议里**没有**客户端注册工具的入口 | Godot 没法自己声明 `set_background` |
| 工具结果 | `/api/message` 只收 `{ text }`,**没有**回传工具结果的端点 | 就算收到 `tool_call`,也没法告诉模型「做完了」 |

所以 **需求 7(AI 调画面)在纯客户端方案下不可能成立**。必须在 assistant 进程里加一个插件补上这条双向通道。

好消息是,dsh 底层的能力全都在,只是没接出来:

| 能力 | dsh 提供的 API | 用来做什么 |
|------|---------------|-----------|
| 运行时注入系统提示词 | `ctx.systemPrompt.section({ name, order, text })`,返回 disposer,`text` 可以是函数(每次组装时求值) | **需求 4** —— 客户端连上才注入,断开就撤掉 |
| 运行时注入动态上下文 | `ctx.systemPrompt.context(...)` | 把「当前舞台长什么样 / 已有哪些图可复用 / 哪些路径失效了」每步喂给模型 |
| 运行时增删工具 | `ctx.tools.register(def)` 返回 disposer;**同名重复注册会抛异常,必须先 dispose** | **需求 7** —— 客户端连上才注册演出工具,断开就撤掉 |
| 长时间阻塞的工具 | `execute(args, exec)`,`exec.signal` 是唯一取消通道,不设 `timeoutMs` 就不超时 | AI 反问用户时,工具挂起等点击 |
| WebSocket | `@deepseek-ai/dsh-host-webserver` 的 `WebUpgradeRoute`;`ws` 已在 assistant 依赖里(装了没用) | 补上双向通道 |
| 取消 turn | `agent.cancel({ kind: 'user' })` | Esc 打断 |

于是模块拆成两半:

```
assistant-godot/
├── (模块根即 Godot 工程)  ← project.godot / autoload / core / scenes
└── bridge/   ← cordis 插件,塞进 assistant 进程(约 600 行 TS,不可省)
```

**部署关系见 `docs/diagrams/01-deployment.puml`。**

## 3. 一条关键决策:连哪个助手实例

`ctx.systemPrompt.section` 是**进程级**的(一个进程只有一个 agent)。也就是说:VN 客户端一旦连上某个助手,「你在视觉小说场景里/回答要简洁」这套提示词会作用于该进程的**所有**客户端,包括 web-ui 和 console。

> **建议:给 VN 开一个专用助手实例**(如 `:3011`,`sessionId = assistant-vn`),由 console 的 spawn API 拉起。编码助手 `:3001` 完全不受影响。

代价是:记忆(`~/.assistant/assistants/{sessionId}/memories`)和会话是独立的,VN 助手不认识编码助手记过的事。

> **待你拍板(§16 Q1)**:接受独立记忆,还是希望 VN 与日常助手共用一套记忆?后者需要额外做记忆目录共享,不是白拿的。

## 4. 分层

**见 `docs/diagrams/02-layers.puml`。**

| 层 | 名字 | 职责 | 关键约束 |
|----|------|------|---------|
| L5 | 表现层 Presentation | Godot 节点、场景、Shader、输入 | 只调 L4 的 API,只订阅信号 |
| L4 | 演出层 Direction | 把「指令」翻译成动画;分页与节奏;资产解析 | 唯一能碰 L5 节点的层 |
| L3 | 领域状态层 Domain State | 舞台状态、台词模型、Backlog、连接态 | 纯数据,可序列化(存档靠它) |
| L2 | 协议层 Protocol | 帧解析、展示过滤、流式拼接、工具网关 | **不引用任何 Node**,可无头测试 |
| L1 | 传输层 Transport | WS 收发、HTTP 补齐、重连退避 | 面向 `ITransport` 接口,可替换为 Mock |

**依赖规则**(重要,决定了这套东西好不好改):

1. 上层可以调下层的接口;**下层永不引用上层类型**,只用 Godot 信号往上抛事件。
2. L1–L3 是纯 `RefCounted` GDScript,不 `extends Node`,不碰 `get_tree()`。→ 可以在 `--headless` 下跑单元测试,不起窗口。
3. L4 是唯一的「桥」:它拿着 L3 的状态,去驱动 L5 的节点。L5 里不允许出现协议概念(`turn`、`callId`、`chunk`)。
4. 装配在 `autoload/services.gd` 一处完成(组合根)。其他地方不 `new` 依赖。

这套规则的实际收益:**换掉传输协议不影响演出;换掉美术不影响协议**。以后 assistant 真把官方 WS 实现了,只动 L1。

## 6. VN 协议

在 assistant 现有 HTTP 服务上挂 upgrade 路由,**不新开端口**:`ws://127.0.0.1:3011/ws`。
沿用现状:默认 loopback；当前代码已支持平台 API Key，助手端通过 `--api-key` / `ASSISTANT_API_KEY` 注入。

### 6.1 客户端 → 服务端

| 帧 | 载荷 | 说明 |
|----|------|------|
| `hello` | `protocolVersion`, `client`, `promptFragment`, `stageState`, `catalog`, `staleAssets`, `allowedRoots`, `tools`, `debug` | 握手。**一次性给全**:系统提示词正文、恢复后的舞台状态、资产目录摘要、失效清单、想暴露的工具 |
| `say` | `id`, `text` | 用户说话 |
| `cancel` | — | Esc,映射到 `agent.cancel({kind:'user'})` |
| `stage_result` | `callId`, `ok`, `value` / `error` | 工具回执 |
| `ping` | — | 15s 心跳 |

### 6.2 服务端 → 客户端

| 帧 | 载荷 | 说明 |
|----|------|------|
| `welcome` | `sessionId`, `assistantName`, `model`, `turn`, `acceptedTools` | 握手结果 |
| `say_begin` | `turn` | 开始说话 |
| `say_delta` | `text` | 台词增量。**只来自 `text-delta`** |
| `say_end` | `turn`, `text` | 本轮**完整终稿**。用于对账 |
| `busy` | `phase: thinking\|working`, `since` | 只说「在忙」,**不说在忙什么** |
| `stage_invoke` | `callId`, `name`, `args`, `awaitUser` | AI 要改画面 / 要反问 |
| `turn_end` | `turn`, `reason` | 一轮结束 |
| `error` | `message`, `recoverable` | 以系统吐司呈现,不当台词 |
| `raw` | 原始 dsh 事件 | **仅当 `hello.debug = true`**,给 DebugOverlay 用 |

### 6.3 两个值得说明的地方

**① `say_end` 带完整文本 —— 这是 bridge 白赚的一项。**
现有 `/api/stream` 的 `assistant_message` 帧把 `content` 丢掉了,web-ui 只能靠累加 delta 还原。bridge 直接读 dsh 的 `assistant/message` 事件,能给出终稿。客户端因此可以**以终稿为准**修正流式拼接的丢字/截断。

**② 过滤在 bridge 做,客户端再防一道。**
`reasoning-delta` 在推理模型上可能是正文的好几倍。在服务端就丢掉,省带宽也省客户端的解析。客户端的 `PresentationFilter` 只做防御:遇到不认识的帧类型一律忽略,绝不「兜底显示」。
`/api/stream` 保持原样不动 —— console 和 web-ui 仍然看得到完整信息。

## 7. 额外的系统提示词

### 7.1 注入机制

客户端在 `hello` 里把 `prompts/vn_scene.md` 的正文发给 bridge,bridge 注册:

- `ctx.systemPrompt.section({ name: 'vn:scene', order: 50, text: <正文> })` —— 静态规则,连接期间常驻(order 50:排在 persona 之后、工具指引之前)。
- `ctx.systemPrompt.context({ ... })` —— **动态**,每一步重新求值,喂当前舞台状态与可用资产。

客户端断开 → 两个 disposer 一起调用 → 提示词干净消失,助手变回原样。

好处:**提示词是 Godot 项目里的一个 md 文件**,调语气不用碰 TypeScript、不用重启助手。

### 7.2 正文要写什么(要点;完整稿在 M2 定稿,依赖 Q2 的角色设定)

1. **场景设定** —— 你在一个视觉小说式的界面里和用户对话;用户看到的是你的立绘和一个对话框。
2. **长度** —— 一次一到三句。对话框一屏放不下多少字,长回答会被切成好几页,用户要连点。
3. **静默执行** —— 用户让你做事,直接做。不要播报「我现在要读取文件」「让我搜索一下」。做完只说结果。
4. **不复述过程** —— 不列步骤、不贴代码块、不用 Markdown 标题和项目符号。要给代码或长内容,写进文件再口头告诉用户路径。
5. **有疑问就问** —— 用一句自然的话反问,或者调 `vn_ask` 给两三个选项。不要自己瞎猜着往下做。
6. **演出自觉** —— 场景有明确变化时才调工具。不要每句话都调,也不要通篇不调。情绪切换用内联标记(§9.3),别为它单开一次工具调用。
7. **失败也用说的** —— 出错了就用一句话讲清楚卡在哪,不要贴堆栈。

### 7.3 动态上下文喂什么

每步注入一小段(控制在 ~250 token):

| 内容 | 为什么必须有 |
|------|------------|
| **当前舞台状态** —— 背景是什么、角色是谁、当前情绪、场上有哪些道具 | 模型不看屏幕。不告诉它,它就不知道现在长什么样,会重复布置已经布置好的东西 |
| **资产目录摘要** —— 已有哪些图可以直接复用(路径 + 当时的描述) | **省钱省时间的关键**。没有这个,模型每次想换场景都重新生成一遍(§10.2) |
| **各情绪槽的填充情况** | 让它知道 `angry` 还没生成,该补 |
| **失效清单** —— 哪些图片路径已经找不到了 | 否则它以为背景还在,永远不会主动补,用户一直看着空舞台(§9.6) |
| 上一次工具调用的结果与 warning | 让它学会用对参数 |

> 核心思路:**模型看不见画面,所以画面状态必须变成文字喂给它。** 这比在提示词里写「请选择合适的背景」有用得多。

### 7.4 角色档案:名字、性格、说话风格全可配

不写死在代码里。`profiles/<id>.json` 一个文件描述一个角色:

| 字段 | 用途 |
|------|------|
| `name` / `displayName` | 名牌显示 |
| `personality` | 性格描述,填进提示词模板 |
| `speechStyle` | 说话风格(语气、口癖、称呼、句长偏好) |
| `artStyle` | 画风描述。助手生成立绘时参考它,保证多次生成风格一致 |
| `spriteSet` | 已生成的部件集目录;为空则触发首次角色创建流程 |
| `voice` | 预留给 TTS |

`prompts/vn_scene.md` 里用占位符引用这些字段(`{{name}}`、`{{personality}}`、`{{speechStyle}}`),bridge 组装时替换。

**热切换**:因为 `systemPrompt.section` 的 `text` 可以是**函数**(每次组装时求值),切换档案**下一轮就生效,不用重启助手**。这是 §2 那个发现白赚的一项。

> 多档案的直接好处:同一个助手可以有「工作模式」和「闲聊模式」两个形象与语气,切换成本是点一下。

## 8. 展示过滤

| 收到 | VN 客户端行为 |
|------|--------------|
| `turn_start` | 进「思考」态。**>800ms 才**显示「…」气泡(短回答不闪) |
| `reasoning-delta` | **丢弃**。只取「还在动」这个信号,维持忙碌指示 |
| `text-delta` | 进打字机 |
| `tool-call-request` / `tool_call` / `tool_result` | **全丢**。工具名、参数、结果一律不上屏 |
| 工具执行中 | 切到 `thinking` 情绪槽(未填则不变);**>3s** 才追加一句无害的等待台词(如「稍等」) |
| `assistant_message` | 取终稿,与流式缓冲对账 |
| `turn_end` | 收尾,输入栏回来 |
| `error` | **系统吐司**,不进对话框、不进 Backlog —— 模型报错不该由角色背锅 |
| 未知帧 | 忽略,写日志 |

**开发期怎么办?** F3 打开 DebugOverlay,`hello.debug = true` 让 bridge 额外推 `raw` 帧,能看到全部被丢弃的思考与工具。默认关闭,发布版可编译掉。这样「完全不展示」和「能调试」不矛盾。

## 9. 演出系统

### 9.1 Director

所有画面变更都走 `Director.submit(StageCommand)`,不允许任何地方直接改节点。理由是**冲突仲裁**:AI 可能在上一次淡入还没放完时又发一条换背景。

规则:

- **同层后来者胜**:新的背景指令直接接管,旧 Tween 从当前进度过渡,不排队等。
- **异层并行**:换背景 + 换表情 + 起风,同时进行。
- **立即回执**:指令入队就返回,**不等动画放完**。否则模型每改一次画面要多等一秒。除非显式 `awaitComplete`。
- **幂等**:目标态相同则跳过,不重放动画。

### 9.2 暴露给 AI 的工具

**核心原则:客户端工具只做「呈现」,不做「生成」。**
它们全部只接受**图片路径 + 参数**,由客户端去加载和摆放。图片怎么来的,工具不关心 —— 助手用它自己的生图能力另外解决(§10.1)。

这条分工让两边都变简单:客户端不必内置任何生成逻辑、不必管 API key 和网络;助手可以用任意生图手段,换生图工具不影响客户端一行代码。

| 工具 | 阻塞 | 干什么 | 频率 |
|------|------|--------|------|
| `vn_set_character` | 否 | 注册/替换角色:名字 + **一整套情绪立绘的路径** | 极低(一次性) |
| `vn_set_scene` | 否 | 换背景:一个图片路径 + 转场 | 低 |
| `vn_add_prop` | 否 | 往场景里加东西:图片路径 + 坐标 + 层级 | 中 |
| `vn_remove_prop` | 否 | 拿掉 / 移动 / 清空场景内容 | 中 |
| `vn_ask` | **是** | 反问 + 2~4 个选项,挂起等用户点 | 低 |

情绪切换**不在这张表里** —— 它是最高频的操作,走内联标记,零成本。见 §9.3。

#### `vn_set_character` —— 角色与情绪模板

情绪槽位是**固定的标准集**,客户端定义,不由 AI 自创:

```
neutral（必填，兜底用） · happy · sad · angry
surprised · thinking · embarrassed · tired
```

参数形如:

| 字段 | 说明 |
|------|------|
| `id` | 角色标识,如 `"yui"` |
| `name` | 名牌显示名 |
| `sprites` | 情绪槽 → 图片路径的映射。**只填 `neutral` 也能工作** |
| `anchor` | 立绘锚点,默认 `bottom_center` |
| `scale` | 相对舞台高度的占比,默认 0.9 |

关键设定:

- **槽位固定 ⇒ 客户端永远知道该显示什么。** AI 说 `[[happy]]` 而 happy 槽为空 → 自动回落到 `neutral`,并把「happy 槽未填」作为 warning 回给模型。**画面永不空白。**
- **可增量补充。** 第一次只给 `neutral`,后面想到了再补 `angry`,不用重新注册整个角色。
- **整张立绘,不做分层部件。** 这一点是你定的,也是对的:图片生成器很难产出可分离且风格一致的部件(眉毛单独一张图,风格必然飘),但「同一角色换表情」它靠参考图/img2img 做得到。

#### `vn_add_prop` / `vn_remove_prop` —— 场景内容加减

| 字段 | 说明 |
|------|------|
| `id` | 道具标识,用于后续移除/移动。重复 id = 替换 |
| `image_path` | 图片路径 |
| `slot` **或** `x`/`y` | 位置。二选一,见 §9.5 |
| `scale` | 相对舞台高度占比,默认 0.2 |
| `layer` | `behind_character` / `front_character`,默认 behind |
| `transition` | `none` / `fade` / `pop`,默认 fade |

`vn_remove_prop` 支持 `id`(单个)或 `all`(清空)。移动位置直接用同 id 重新 `add`(幂等替换),不单开一个 move 工具。

> **工具数量的取舍**:我原本主张只给 3 个工具(工具越多模型越容易选错)。你要的加减场景内容确实需要独立的动作语义,所以这里给到 5 个。没有把它们合成一个带 `action` 字段的大工具 —— 单一职责的工具,模型选得比 action 派发准。

工具的生命周期绑定客户端连接:连上时注册,断开时 dispose。
> 注意 dsh 的契约:**同名工具重复注册会抛异常**,重注册前必须先 dispose。

### 9.3 表情为什么不走工具

高频微调走工具,代价太大:一次工具调用是一个完整的 LLM 往返(~1–2s),而且表情只能在整句话之前或之后变,没法跟着语气走。

**方案:内联标记。** 模型在台词里写 `[[smile]]`,`StreamAssembler` 在流式阶段就地剥离并触发表情切换。零额外延迟,能在句子中间变脸 —— 这正是视觉小说脚本的写法。

难点是**跨 delta 截断**:`[[smi` 和 `le]]` 可能分在两个 chunk 里。处理办法是「未闭合缓冲」—— 结尾出现可能是标记前缀的片段就先扣住不上屏,等下一个 delta 拼上再判定。turn 结束时若仍未闭合,按普通文本吐出。

分工因此很清楚:

| | 走工具 | 走内联标记 |
|---|-------|-----------|
| 频率 | 低 | 高 |
| 粒度 | 场景级 | 句子级 |
| 例子 | 换角色、换背景、加道具、反问 | 切情绪(`[[happy]]`) |
| 代价 | 一次 LLM 往返 | 0 |

> 所以 §9.2 那张表里**没有**「切情绪」这个工具 —— 情绪立绘由 `vn_set_character` 一次性注册好,之后靠标记切换。生成一次,切换无限次。

### 9.4 反问怎么做成 VN 的样子

`vn_ask` 是**阻塞工具**:`execute` 挂起,直到客户端回执或超时。dsh 允许这么做(不设 `timeoutMs` 就不超时),但必须监听 `exec.signal`,否则用户按 Esc 取消不掉。

三种收场:用户点选项 → 返回选项;用户无视选项直接打字 → 返回 `{choice: null, reason: "user_typed"}`;超时 → 返回 `{choice: null, reason: "timeout"}`。后两种让模型知道该改走纯对话,而不是干等。

**见 `docs/diagrams/05-seq-stage-tool.puml` 情形 C。**

### 9.5 坐标系:为什么给槽位也给坐标

模型给精确像素坐标是不太行的 —— 它看不见画面,也不知道你的窗口多大。所以两套都提供:

**① 命名槽位(推荐,模型优先用)**

```
        far_left   left   center_left   center   center_right   right   far_right
 top        ·        ·         ·          ·           ·           ·         ·
 middle     ·        ·         ·          ·           ·           ·         ·
 bottom     ·        ·         ·          ·           ·           ·         ·
```

`slot: "bottom_right"` 之类。客户端负责换算成实际坐标,并做**避让**:同槽位已有东西就自动错开一点,不叠在一起。

**② 归一化坐标(需要精确控制时)**

`x` / `y` 取 `0.0–1.0`,相对舞台左上角。**不用像素** —— 分辨率无关,换窗口大小不用重算。越界值 clamp 回 `[0,1]` 并回一条 warning。

同理 `scale` 也是相对舞台高度的占比,不是像素尺寸。

### 9.6 舞台是**粘性**的:只有 AI 的工具调用能改它

这条决定了不少实现细节,单列出来。

**规则:舞台一旦被布置,就一直是那样 —— 关掉客户端重开、重连助手、切场景,都不变。唯一能改变它的是 AI 再调一次工具。**

推论(都是「不做什么」):

- ❌ 不在 turn 结束时重置任何东西
- ❌ 不做「自动表情」之类的启发式 —— 客户端不擅自替 AI 做演出决定
- ❌ 不做定时轮换背景、随机待机换装
- ✅ 客户端在演出上是**纯执行者**,零自主性

#### 存什么、存哪

`StageState` 序列化到 `user://stage/<sessionId>.json`。**按 sessionId 分文件** —— 换助手实例就是换一套舞台,互不干扰。

存的内容:

| | 说明 |
|---|------|
| 角色注册信息 | id / name / anchor / scale / **各情绪槽的图片路径** |
| 当前情绪 | 也存。重载后接着上次的表情,而不是跳回 neutral |
| 背景 | 图片路径 |
| 道具列表 | 每个 id 的路径 / 位置 / scale / layer |
| 资产目录 | §10.2 的 catalog,同样按 session 存 |

写入时机:每条指令**成功施加后**防抖写盘(约 500ms)。不在指令入队时写 —— 失败的指令不该留下痕迹。

#### 启动顺序

**先恢复舞台,再连助手。** 顺序反了会有一瞬间的空画面闪烁。

```
读 config → 读 stage/<sessionId>.json → 校验图片路径 → 布置舞台 → 连 WS → 握手
```

#### 路径失效怎么办

外部图片路径会消失(临时目录被清、用户手动删了)。恢复时逐个校验:

- 失效的**背景** → 退回中性底色
- 失效的**情绪槽** → 该槽标记失效,回落 `neutral`
- 失效的**道具** → 不实例化,从状态里移除
- 然后:**把失效清单通过 `systemPrompt.context` 告诉模型**(§7.3),让它知道「你之前那张雨天背景没了,要重新生成」

这条很重要 —— 否则模型以为背景还在,永远不会主动补,用户就一直看着空舞台不明所以。

## 10. 图片从哪来

### 10.1 生成与呈现彻底解耦

```
   助手（用它自己的生图能力）              Godot 客户端（只管呈现）
   ┌────────────────────────┐            ┌──────────────────────────┐
   │ 调生图工具 / MCP /      │  图片路径   │ vn_set_character         │
   │ 本地脚本 / 手工素材      │ ─────────► │ vn_set_scene             │
   │ → 落到磁盘某个路径       │            │ vn_add_prop              │
   └────────────────────────┘            └──────────────────────────┘
```

客户端**不内置任何生成能力**:不管 API key、不发网络请求、不做 SVG 校验。它只做四件事 —— 校验路径、加载图片、摆到位、记进目录。

好处很直接:

- 助手换生图工具(换模型、换服务、改成本地 SD)→ **客户端零改动**
- 客户端不需要网络权限
- 生成失败是助手那边的事,不会把客户端拖进半残状态
- 手工素材、离线批量生成的图、AI 现生成的图,在客户端眼里**完全一样**,都只是路径

### 10.2 资产目录:让生成只发生一次

这是我要额外加的一条,不然会很浪费。

**客户端把 AI 交来的每个路径都登记进一个目录**(`user://catalog.json`):内容哈希、路径、用途(背景/立绘/道具)、AI 当时给的描述、首次使用时间。然后:

1. **每轮把目录摘要通过 `systemPrompt.context` 喂回模型**(§7.3)。模型于是**看得见已经有哪些图**,不会为「窗外下雨的房间」反复生成第二遍、第三遍。
2. **按内容哈希去重**。同一张图换个路径交进来,识别为同一个资产。
3. **失效检测**。路径消失了(临时目录被清)→ 标记失效,并在下次告知模型需要重新生成。

生成一张图有实打实的时间与费用成本,这个目录把它变成**一次性成本**。没有它,模型每次想换场景都会重新生成一遍。

### 10.3 路径安全与加载

**路径白名单。** 配置里给一组允许读取的根目录(如 `~/.assistant/vn/`、客户端自带的 `assets/`)。白名单外的路径 → 拒绝并回原因。

理由不是防模型作恶 —— 助手本来就有文件系统工具,能力上早就更大了。真正要防的是:路径穿越把客户端指向一个巨大文件或设备文件,把客户端拖死。所以配套:

| 检查 | 拒绝条件 |
|------|---------|
| 根目录 | 不在白名单内(解析符号链接后再判断) |
| 扩展名 | 不是 `.png` / `.jpg` / `.webp` / `.svg` |
| 文件大小 | 超过上限(建议 16 MB) |
| 解码后尺寸 | 超过上限(建议 4096×4096) |

**加载方式。** 外部路径的图片不能走 `ResourceLoader`(那要走导入流程),要用 `Image.load_from_file()` + `ImageTexture.create_from_image()`。`.svg` 需要单独走一步:读成文本再 `Image.load_svg_from_string(text, scale)`(已核实存在,`core/io/image.h:470`;注意 Godot 的 SVG 是 ThorVG 的 **Tiny 1.2 子集**,不支持 SVG 动画)。

**失败处理。** 文件不存在 / 解码失败 / 超限 → 工具返回失败并说明原因,**舞台保持原样**。绝不半残上屏。模型拿到原因后可以重新生成或改用目录里已有的图。

### 10.4 冷启动:一开始只有一个对话框

**不自带任何占位美术。** 第一次跑起来,画面上只有一个对话框(加一层中性底色),没有背景图、没有立绘。这是**合法的初始状态,不是缺失状态**。

理由:

- 塞一套占位美术进仓库,最后一定是没人用又不好删的东西;
- 「没有立绘」在渲染上完全成立 —— 就是不实例化那个节点;
- 用户想要形象了,让助手生成就是 —— 这本来就是这套设计的用法。

所以**所有「缺省」都不是错误**:

| 状态 | 表现 |
|------|------|
| 没设角色 | 不显示立绘。名牌显示 `profiles` 里的 `name` |
| 没设背景 | 中性底色(取自主题配色) |
| 设了角色但某情绪槽为空 | 回落到 `neutral` 槽 |
| 连 `neutral` 都没有 | 不显示立绘,并把「需要先注册立绘」回给模型 |

**画面永远不会是黑屏或碎图 —— 只会是「还没布置」。**

### 10.5 仍然不做:AI 直接给 GDScript

理由不变。一是安全 —— 那等于让模型在你机器上执行任意代码;二是可靠 —— 语法错、API 用错、死循环会直接崩掉客户端。

图片路径是**数据**,GDScript 是**代码**。前者通过了后者没通过的那道测试。

## 11. 对话呈现

### 11.1 会话记录

`BacklogStore` 收全部台词(不含被过滤的工具与思考),内存 + `user://backlog.jsonl`。
`BacklogPanel` **默认隐藏**,L 键或向上滚轮呼出,ESC 关。不占任何常驻画面空间。

### 11.2 Markdown 怎么变台词

模型难免会输出 Markdown。`TextSanitizer` 的处理:标题 → 去掉井号变普通句;项目符号 → 合成一句带顿号的话;`**粗体**` → 转成 BBCode 的着色强调;行内 `code` → 保留但换等宽字体;**代码块 → 整块摘掉**,替换成一句「代码我写进 xxx 了」。

同时提示词里已经明确要求不用 Markdown(§7.2)。这里是兜底,双保险。

### 11.3 分页与节奏

按标点和字数切页(默认 ~60 字/页),`▼` 提示续行。空格/点击加速当前页,再按跳到页尾。可配自动前进。

### 11.4 输入

底部输入栏,回车发送。助手说话期间收起(可配「常驻」)。Esc 取消当前 turn。

## 12. 状态机与异常

**见 `docs/diagrams/06-state-machines.puml`**,两台:连接态、对话演出态。

几个必须处理对的边界:

| 情况 | 处理 |
|------|------|
| 助手没启动 | Boot 停在 Offline,给「拉起助手」按钮(走 console 的 spawn API) |
| WS 断了 | 指数退避 1s→30s;重连后 `GET /api/history?before=…` 补齐漏掉的 turn |
| 工具跑很久 | 只显示「忙」,>3s 补一句等待台词,**永不暴露在跑什么** |
| 模型报错 | 系统吐司,不进对话框、不进 Backlog |
| 用户 Esc | `agent.cancel({kind:'user'})`,立绘演一个「被打断」 |
| 单条回复超长 | 分页;超过 N 页给「跳过本段」 |
| 第二个 VN 客户端连进来 | 后连的接管,先连的收到 `error` 并退出。**不做多客户端同步** |

## 14. 测试

- **L1–L3 不 `extends Node`** → GUT 在 `--headless` 下直接跑,不起窗口。
- **录制回放**:`curl -N http://127.0.0.1:3011/api/stream > tests/fixtures/xxx.jsonl` 就能录下真实事件流。`MockTransport` 回放它 —— 于是过滤规则、流式拼接、内联标记截断这些最容易出错的逻辑,**不用起助手也不用花 token 就能测**。
- 重点用例:reasoning-delta 一律不上屏;工具事件一律不上屏;标记跨 delta 截断;终稿与流式不一致时以终稿为准;资产模糊匹配的降级链。
