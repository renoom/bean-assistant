## 发现的问题与修复

1. **压缩服务未声明依赖。** assistant 插件未注入 `compaction`，从插件 Context 访问 `ctx.compaction` 会抛错。旧代码捕获错误后消耗唯一的定时器。已补上 `compaction`、`llm` 依赖。
2. **初始空闲不计时。** 恢复后的 Agent 默认 idle，不补发初始状态事件。旧代码仅监听未来状态变化。现在安装时检查实际 Agent 状态，立即安排空闲检查。
3. **失败后没有重试与状态。** 现在每个空闲周期失败后最多重试两次，间隔仍为 30 分钟；成功或无可压缩历史后等待新一轮活动。关闭时取消计时器并中止正在执行的压缩请求。
4. **原文读取可能先于写入。** 现在提取前等待原文写入队列；重启时从持久会话补录缺失原文，按事件 seq 去重；关闭时等待已排队记录完成。
5. **记忆提取沿用旧模型。** 现在优先读取当前配置中心的模型选择，其次读取 Session 最近请求配置，最后使用 Agent 初始配置。提取请求支持取消和 60 秒超时；提取失败时仍保留已保存的摘要记忆。
6. **自动召回只接受普通用户输入。** 现在也处理 Stage 客户端的事件输入，从事件 JSON 的可读字段提取检索文本。使用最新输入，增加有上限的关键词检索，不再注入空标题；已有相同召回仍在当前 surface 时不重复注入，压缩移除后可以再次召回。

## 当前触发规则

- **空闲压缩：** 助手连续空闲 30 分钟后检查；启动恢复时已经空闲也计时。新的运行轮取消计时，结束后重新开始。成功或无需压缩后不会每隔 30 分钟重复压缩同一份历史。
- **上下文压力压缩：** DSH 原生 `compaction-basic` 继续在模型步骤前按上下文压力触发，当前默认阈值为模型上下文窗口的 80%。它与空闲计时是两条独立触发路径。
- **压缩产物：** DSH 将选定 surface 区域替换为摘要，原始 Session 历史继续保留。助手将摘要保存为私有 Markdown 记忆，再从可追溯原文提取偏好、事实和决策。
- **环境知识：** Stage 的当前环境仍由 Stage 管理器独立维护，不依赖被压缩的普通对话消息。

## 可观察状态

助手管理接口 `/api/status` 与 `/api/observability` 新增 `memory.idleCompaction`：

| 字段 | 含义 |
| --- | --- |
| `idleMs` | 空闲等待时间，默认 1,800,000 毫秒 |
| `nextRunAt` | 下次检查的毫秒时间戳；无等待任务时为 null |
| `running` | 是否正在执行空闲压缩 |
| `lastRunAt` | 本进程上次检查时间 |
| `lastOutcome` | compacted / skipped / failed / cancelled |
| `lastError` | 最近失败原因 |

助手 WebUI 的观测面板展示下次检查时间和结果；失败原因可通过悬浮提示或管理接口查看。上述计时状态属于当前进程，重启后会重新安排，历史压缩事件仍在 Session 中。

## 回归验证与边界

测试使用临时目录、原生 DSH Session / AgentLoop / JSONL 持久化 / 压缩事务和模拟模型，不触碰真实助手的对话或调用付费模型。

- 验证初始 idle、运行状态重置、无可压缩历史、失败重试上限、关闭取消与依赖注入。
- 验证原生压缩生命周期、摘要与精细记忆落盘、原文范围溯源、当前模型选择和提取失败的保底处理。
- 验证恢复原文补录去重、立即读取等待写入，以及普通输入和场景输入召回。
- 保留现有 Stage 恢复测试，验证当前环境恢复后不会留下失效的可调用 bridge。
